Orbit mini-shop

目標很簡單：選客戶 → 加入購物車 → Checkout。你不用先記 API，也不用先猜 service 邏輯。

這個 demo 想證明 3 件事：主機與容器混合、跨 service 的資料關聯、以及發生問題時可以快速定位。

場景導演（先做這 3 個）

每個情境都會顯示「你做了什麼 → 會看到什麼 → 下一步」；先做 A，再做 B、C。

情境 A：成功下單（最重要）

目標：看到一次完整的訂單與出貨關聯。

期望：產生一筆 confirmed 訂單，並在出貨列表看到對應 order_id。

情境 B：付款失敗（故障最小化）

目標：驗證失敗訊息是否清楚，且知道該怎麼修。

期望：回傳付款失敗類錯誤碼，且介面會顯示改用 mock_card 重試。

情境 C：庫存不足（邏輯保護）

目標：知道庫存不足時，checkout 如何阻斷且不新增錯亂資料。

期望：顯示 insufficient_stock，且訂單/出貨沒有被新增。

（註）若看到關聯成功，代表你這一輪不是真正庫存不足，請先清空購物車再重跑。

故障演練（1/2 分鐘）

這是給「真的會壞掉」的情境設計：先建立成功 baseline，再停止一個 service，接著照步驟恢復。

  1. 先點「先做一輪成功流程」建立可重播 baseline。
  2. 在 terminal 貼上「停止 cart-api」命令，模擬單點故障。
  3. 貼上「檢查狀態」找出卡住節點並回到對應卡片。
  4. 貼上「重啟 cart-api」讓服務恢復，最後用「回到 3 秒可 demo 指標」確認回歸。
尚未開始故障演練，等待 1 次回歸結果。
尚未建立基線時，請先按「先做一輪成功流程」。

目標是確認流程能在不離開頁面思路的情況下，完成「故障→定位→恢復→回歸」。
