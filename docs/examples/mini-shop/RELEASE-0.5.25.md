# Orbit Mini-Shop (0.5.25) — 降低回報認知負擔

## 目標

把 demo 驗收流程再往「可交付」再推一步：除了能跑、能回歸之外，
也要能把結果快速整理給別人看，讓使用者不必自己組合「到底有沒有達到可 demo」這件事。

## 本版亮點

### 1) 一鍵複製 demo 報告

在 `第一次 demo（30 秒）` 區塊新增：`複製 demo 報告`。

點一下會複製當前狀態摘要（含）：

- 服務就緒信號（8/8）
- 交易信號（是否成功 checkout）
- 關聯信號（是否關聯到出貨）
- 最近訂單、出貨、最後 checkout 結果
- 下一步建議

這樣 demoer 可以直接把結果貼到 PR、issue、Slack，
省去「要不要再看三個卡片」的額外心智轉換。

### 2) 一鍵複製故障回歸報告

在「故障演練（1/2 分鐘）」新增 `複製故障回歸報告`，並將以下欄位一併輸出：

- 基線耗時（先做一輪成功流程）
- 回歸耗時（回到 3 秒可 demo 指標）
- 服務 / 交易 / 關聯信號
- 訂單與出貨快照
- 回歸可交付結論（是 / 否）

這能讓使用者把「故障演練是否完成」變成可貼報告的結論，不用手工整理時間與狀態。

### 3) 文件同步

`docs/examples/mini-shop/README.md` 已補上「複製 demo 報告」的使用說明，讓新手第一次啟動時知道
這個按鈕是「對外同步」的入口。

## 驗收補充

- 在「第一次 demo（30 秒）」完成一次成功流程後，點 `複製 demo 報告`，貼到訊息中應可直接閱讀：
  - `服務信號：綠/未全綠`
  - `交易信號：綠/未完成`
  - `關聯信號：綠/未關聯`
  - 最近訂單與出貨是否一致
  
- 在「故障演練」完成 baseline + 回歸驗證後，點 `複製故障回歸報告`，可直接複製：
  - `基線耗時`
  - `回歸耗時`
  - `回歸可 demo`
  - `故障演練結論`

- 仍可保留舊有故障演練腳本與 `故障演練` 流程不變，報告按鈕純粹是「輸出結果」而非替代修復流程。

## 對 1.0 打磨目標的影響

- 類型：UX 細節優化
- 影響：降低新手 demo 之後「要怎麼回報」的認知負擔
- 對應原則：讓第一步更可被衡量、第二步可直接分享、第三步減少 context 切換
