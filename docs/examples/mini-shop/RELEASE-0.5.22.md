# Orbit Mini-Shop (0.5.22) — 1.0 前體驗打磨版

## 目標

- 讓第一次開啟 demo 的使用者，不需要先理解全部服務，能在最短時間拿到可驗證結果。
- 讓每個失敗狀態有「下一步要怎麼做」而不是只看到紅字。
- 讓 release review 清楚看到這個版本有沒有新增使用者價值（而不只是版號變更）。

## 核心改善（使用者直接感受）

- 加入「現在只要做一件事」的單一步驟面板。
  - 依目前狀態自動更新：服務待就緒、先選客戶、加商品、做 checkout、核對結果。
  - 每一步都提供可點擊的建議行為（不是只是文字解釋）。
- 新增「第一次 demo（30 秒）」：
  - 開始 demo 一輪（直接跑成功 path）
  - 核對可 demo 條件
  - 先看 1.0 檢核清單
- 加入「快速判斷值（服務 / 交易 / 關聯）」：
  - 三個指標同時綠，等於可對外 demo；不用先追 service log 才能決定可否示範。
- 加入「關聯完整性快檢查」：
  - 不看原始資料也能看到「最近 checkout 是否已關聯出貨」。
- 新增「1.0 交付前檢核」：
  - 服務就緒
  - 成功 checkout
  - 訂單與出貨關聯成功
- 新增「最短重現路徑」：
  - 成功 / 付款失敗 / 庫存不足，一鍵到可驗證結果。
- 新增新手 / 進階模式切換：
  - 預設新手模式（流程主線）；進階模式展開更多診斷與操作回應，避免一開始資訊噪音過大。
- 錯誤導向卡牌升級：
  - 故障卡改為可展開；同時保留一鍵「主要修復動作」，再補同檔案/命令級建議。

## 使用者心智模型降低的證據（每次驗收可看）

1. 開啟頁面後，不需要先看所有卡片。
2. 先按「開始 demo 一輪」，再按「核對可 demo 條件」。
3. 三格都綠後，才把 demo 視為可展示狀態。
4. 任一失敗都可以先在同一頁面完成「定位 + 動作建議」，不是先猜流程。

## 技術層面驗證建議

- 功能對齊：
  - `/docs/examples/mini-shop/README.md` 的「首次最小心智體驗」更新為以 30 秒 demo 為起點。
- 可用性核對（手動）：
  - 服務 8/8 ready + web 正常（`status --json`）
  - 1 次 `mock_card` 成功 checkout
  - 快速判斷值與 1.0 檢核清單同時通過

## 後續 1.0 打磨待辦

- 對「關聯完整性」補更多場景（例如重試/非同步回滾）邏輯可視化。
- 新增「離線/重連」情境，確認使用者仍能用同樣步驟恢復。
- 對外文件補一頁「為什麼這個 demo 會比較不一樣」（對比舊版多服務 demo 的使用者流程）。
