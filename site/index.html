CORE WORKFLOWS

Run, update, and debug the local stack.

01 / RUN

Start the stack in dependency order.

orbit up starts independent branches in parallel and waits for declared health checks before starting dependents. The dashboard shows each transition in real time.

One commandServices and infrastructure
Health-gatedDependency-aware startup
Live graphCurrent resource state

Generic dashboard screenshot will be captured from orbit-demo.

02 / UPDATE

Publish database changes without rebuilding the image.

orbit db publish AppDB builds the DACPAC on the host and publishes the schema diff straight to the running SQL Server. Idempotent, data preserved, sibling databases untouched.

Generic database screenshot will be captured from orbit-demo.

03 / DEBUG

Follow a request across services.

Orbit joins logs and OpenTelemetry spans by exact trace and span IDs. Inspect the waterfall, open related logs, or replay the request on the service graph.

ONE LOCAL CONTROL PLANE

Replace separate tools with one shared view.

Separate local workflows

  • Different startup steps across repositories
  • Resource state split across terminals and Docker tools
  • Database changes tied to image rebuilds
  • No stable interface for development agents
→

Orbit

  • One environment model, CLI, and dashboard
  • Visible topology, health, logs, and traces
  • Reliable process-tree shutdown
  • Structured JSON output for automation and agents
